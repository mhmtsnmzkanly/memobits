# Implementation review — 2026-11-17

This point-in-time review compared primitive execution and array analysis
with accepted decisions. See the [implementation plan](implementation-plan.md)
for current status. Implementation files were not changed during review.

## Confirmed findings

### P2: zero repetition incorrectly executes element control flow

`crates/memobits-analysis/src/types.rs:219` uses the repeated element flow
regardless of count. This type-checks without the required function result:

```text
fn f() -> i32 {
    let a: array<array<i32, 1>, 0> = [[{ return 1; }]; 0];
}
```

Zero repetitions evaluate no elements, so the body falls through and must report
its missing i32 result. Keep type/name checking of the element independent from
runtime flow. Add zero-count return, divergence, break, and continue regressions
before enabling array IR.

### P2: divergent repetition produces an incompatible array element type

`crates/memobits-analysis/src/types.rs:861` wraps a divergent expression in an
array instead of accounting for contextual type and evaluation flow:

```text
fn f() {
    let a: array<i32, 1> = [{ return; }; 1];
}
```

This reports TE002 with `array<never, 1>`, whereas the equivalent list literal
`[{ return; }]` passes. Repetition must distinguish zero count from positive
count and preserve the appropriate flow. Add matching list/repeat regressions.

Both findings were reproduced through CLI analysis. Array executable IR remains
rejected, so these do not currently produce unsafe Wasm array programs.

## Alignment and limits

The workspace/crate structure, primitive move/reference checks, internal Wasm
reference execution, and shared source/artifact runner follow the accepted plan.
No additional concrete defect was reproduced in the reviewed Wasm owner-cell,
frame-bound, reborrow, export-guard, or operand-order paths. This bounded review
is not a proof of ownership soundness.

Array ownership, indexing, executable layout, dynamic collections, strings,
package linking, per-definition incremental caching, optimization measurements,
and stable external ABI remain unfinished. Syntax/type-only array support must
not be reported as executable array support.

Several earlier implementation-plan sections still say borrow/share is
unsupported and are contradicted by later checkpoints. Consolidate current
status into one section so readers do not have to interpret historical entries.

Trap cleanup intentionally discards instances in the current runner. Reusing a
trapped Wasm instance requires a reset/discard policy; this documented limitation
is not a new defect.
