## Decision boundaries

- **Accepted.** Owned values move, borrows are read-only, and shares are exclusive without transferring ownership. A share requires a mutable owner. Distinct places may be disjoint. Last use ends a loan. Operands and arguments evaluate left to right. Assignments finish evaluating the RHS before replacing an owner. Plain integer operations remain checked in every build profile, with explicit numeric alternatives. Floats follow IEEE. Strings remain valid UTF-8. Normal scope exits clean owned storage. A trap discards the instance. [Accepted decisions](decisions.md)
- **Implemented baseline, S1 and S2.** Direct local String fields support literals, named heap moves, concat and direct internal String results. Constructors stage owners and release staged allocations on early exits. Direct mutable-local field replacement stages RHS values, and whole local moves transfer cleanup. Direct internal calls can accept a borrow or share of a named String-owning struct owner; the exclusive share leaves cleanup with the caller. S2 also permits direct String-field replacement through that parameter with the same RHS forms; stored or forwarded shares, whole-record replacement, owned struct argument/result transport and nesting remain gated. [Current ownership contract](owned-heap-foundation.md#local-structs-with-string-fields)
- **Selected limits for this tranche.** S1 uses existing `share` syntax and direct call shape. S2 handles direct String fields through that exclusive parameter. N1–N3 define narrow portable numeric foundations for the hashing workload. The order and width limits are implementation scope choices.
- **Numeric decisions.** The accepted surfaces are recorded in [the inventory](feature-inventory.md#types-numerics-and-functions-as-values). The user approved casts, wrapping methods, bitwise forms, precedence and bounded unsigned shifts. The older hashing workarounds are baseline fixtures. Cast precedence is a delegated parser choice below. Signed shift semantics for primitives remain excluded.

## S1. Direct internal share of a String-owning struct

**Input.** An explicit `owner.share()` directly in a direct internal call to a `share Record` parameter. The owner is a named mutable local of a currently supported flat, non-Error struct with primitive and direct String fields. The borrowed-struct validation in `crates/memobits-wasm/src/lib.rs` provides the starting point. Trace the direct share-string path in `crates/memobits-ir/src/scoped_string.rs` and the loan checks in `crates/memobits-ownership/src/loans.rs`. Reuse existing reference ABI and the caller address.

**Contract.** The call transfers exclusive access for the loan's duration. The caller remains the sole owner. The parameter receives no owned descriptor or exit cleanup. A callee can read supported fields and borrow a String field for a read. S2 permits direct String-field replacement, with ownership-checked field loans and caller cleanup. Keep aliases, forwarded shares, temporary owners, nested owners, whole assignment, owned arguments, returns, and external parameters gated.

**Acceptance.** Read exact UTF-8 bytes of a heap String and a literal-backed field and verify a primitive field read. The caller can read and move the owner after the call, then release it at lexical exit. Prove the exclusive loan spans later argument evaluation and invocation. Reject immutable owners, overlapping live field or whole borrow/share, a duplicate exclusive argument, owner access or mutation through a competing path, exported and indirect entry forms, alias storage, forwarding and nesting. Keep legal disjoint operations accepted. Exercise a return during later argument evaluation and prove caller-side cleanup. Run the guide and bounded same-instance Wasm verification.

## S2. Replace a direct String field through the exclusive parameter

**Input.** A direct field access on the S1 parameter. Reuse only named owned String, literal, concat and direct internal String-returning RHS forms that are supported on direct mutable local fields. Existing local replacement is represented by `ReplaceStringField`. An arbitrary reference `Store` does not establish proof of which caller field owns the allocation.

**Contract.** Prove the exact caller destination and field across each admitted direct share call. Propagate may-own-heap facts from the replacement back into caller cleanup, including owners initially built entirely from literals, mixed branches and later whole-local moves. Resolve the destination loan at field granularity and preserve disjoint child loans under the exclusive parameter. Evaluate the RHS once before modifying the old field. RHS reads of the old field are legal if their last use precedes the write. A normal early exit abandons the write and cleans already staged allocations. On success, release the old allocation exactly once, transfer the new descriptor and clear the consumed source's allocation provenance. A zero-provenance descriptor needs no release. The callee never ends the caller's struct scope.

**Acceptance.** Cover static-to-heap, heap-to-heap, heap-to-static, self-concat, a direct internal call result, repeated replacement, moves after the call and a control-flow join with only one replacement path. Reject live target or RHS loans, overlapping aliases, whole replacement, forwarded or stored handles, nesting and general temporary RHS forms. Keep a disjoint sibling loan live across an admitted write and check its bytes afterwards. Force early RHS exit and later-argument exit prior to invocation. Create two simultaneous allocations, then repeat source-equivalent workloads on one Wasm instance under a page limit that forces reuse. Check exact field bytes, caller ownership, source invalidation and bounded memory. Retain existing allocator failure and trap behavior. If destination provenance is unproven, retain the write gate.

## N1–N3. Numeric foundations for hashing

Use the same typed operation contract for constants and dynamic code. Preserve parser behavior outside the chosen forms, evaluation order, exact type checks, diagnostic spans, and plain checked addition, multiplication, division and remainder. Do not let Wasm's operand width or wrapping behavior choose source semantics.

| N2 | Explicit `u32` addition and multiplication modulo 2^32. | Verify max plus one, high-bit arithmetic, zero and one, and multiplication across the width. | N3 | Same-width `u32` XOR, AND and OR with ordinary per-bit truth tables. Use approved operators and methods. ## Delegated defaults and major blockers

**Routine defaults to try.** Use a narrow explicit declaration grammar with `borrow self` and existing share/owned vocabulary, postfix `of` and grouped chaining. Recommend `use module;` as an explicit module-edge form *only if* it parses and resolves unambiguously alongside existing symbol imports. Keep flat groups and current `[prelude]` names. Use `<T, const N: u32>` and a `where`-style constraint surface, associated declarations/bindings named `Rhs` and `Output`, and qualify any projection that is ambiguous. Intern symbols by definition identity including package/module. Specialize on concrete types, const values and evidence identity, reusing direct-call IR after elaboration. Cap or diagnose recursive specialization. No host/dynamic dictionary.

Use parenthesized tuples, positional numeric projections, labels as aliases and fully labeled or fully positional initialization. Prefer field-shaped braces only where distinguishable from blocks. Start anonymous contextual enum uses with unique expected types and unit variants. Use distinct nominal identity per declared type occurrence, with payload support through existing enum lowering when the shape is supported. Preserve bodyless declarations separately. For optionals, support expected-type `None` and explicit `Some(expr)` before considering any implicit wrap. Keep grouped borrow precedence and current transport gates. Recommend single-quoted char with existing escapes extended only as needed for one valid Unicode scalar, scalar traversal by value, and byte length unchanged. Keep `Array<T, N>` as the target spelling (decision 2026-11-23), coordinated with lowercase `string` and `T?` when ready. Retain a narrow documented compatibility path outside the target core for old sources rather than layering Bytes into the new core. Start CLI hosting with one explicit profile in `project.toml`, one typed Wasm import, and preflight failure. Prefer cast binding stronger than multiplicative arithmetic and weaker than prefix/postfix, document and test it alongside approved binary precedence.

**Escalate only a material unresolved contract.** A routine syntax choice need not stop the run. Record each chosen default with its limitations. The following are major only if the narrow default cannot preserve an existing contract or would silently settle the listed broader semantics:

- Bodyless runtime values where construction, inhabitance or layout cannot be specified independently of empty structs. Implement declaration identity and supported inherent extensions independently. Gate unsafe construction and report D1 partial if its required execution path cannot be justified.
- New ownership-bearing shapes or comparison RHS access if a narrow exact option still needs reference escape, implicit partial moves, whole heap transport or a change to ordinary receiver access. Keep those operations rejected until proven. Continue the other families or value shapes.
- Cross-package loading/ABI, prelude activation, wider host capability behavior or disambiguation that contradicts agreed visibility rules. Use explicit identities and local-module fixtures for this launch. Do not implement transitive activation or a loader as a workaround.
- Destructive migration or genuinely ambiguous contextual record/enum grammar when preserving existing source meaning is impossible. Keep the compatibility path and report the blocked boundary. Do not needlessly block constructors, tuples, scalar validity or existing calls.

The blocker record must contain the affected manifest row, minimal example and diagnostic, alternatives and why the narrow default failed, the exact question requiring an answer, and the independent work completed. Historical Lang/IDEA backlog, Box, general references, JS host, packaging expansion, and allocator/representation experiments are outside this launch. Their existence is not a blocker.
